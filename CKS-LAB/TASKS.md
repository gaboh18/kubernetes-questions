# Practice tasks

Use `./k8s-sim.sh kubectl ...` on the Mac and `./k8s-sim.sh ssh` for the lab node. Mac files are in `.cks-state/jumpbox`; node fixtures are in `/opt/cks-lab`. `MANUAL` tasks have no automatic points. Keep all active-component changes in a separate disposable Linux environment.

| Q | Task | Validation |
| --- | --- | --- |
| 1 | In the copied `kube-apiserver.yaml`, enable NodeRestriction and ImagePolicyWebhook without dropping existing plugins; configure the staged admission file and mounts. Change `defaultAllow` to false. The staged webhook URL is deliberately invalid. | MANUAL: review syntax here; on a separate VM use a reachable authenticated webhook, then test permitted, denied, and unavailable-backend cases. |
| 2 | In a disposable kubeadm cluster, upgrade from an explicitly recorded baseline to a supported target. Plan/drain as applicable, upgrade control plane and node packages, restore package holds, and uncordon. | MANUAL: actual versions, node readiness, workload continuity; Minikube startup is not a kubeadm upgrade. |
| 3 | Create `backend/default-deny-all` selecting every pod and isolating both ingress and egress. | Config points; additionally prove traffic worked before and is blocked after. |
| 4 | Write a Falco rule for read/write opens of `/dev/mem` with WARNING priority in the staged Falco file. Scale `web/web-backend` to zero after confirming an incident in a real runtime lab. | MANUAL: engine validation, controlled event replay, alert evidence, containment. No unsafe `/dev/mem` access is generated here. |
| 5 | With actual Cilium installed in a separate profile, create `app/restrict-dns`, selecting all app endpoints, allowing egress only to kube-system DNS pods on UDP/53. | MANUAL: test DNS allowance and non-DNS denial; this does not configure encryption. |
| 6 | With a real Istio mesh, enforce mesh-wide STRICT mTLS with `istio-system/default-strict-mtls`; ensure the configured root namespace matches. | MANUAL: enroll workloads, verify encrypted traffic and plaintext rejection. |
| 7 | Modify the jumpbox Dockerfile so its final stage creates `appuser` with UID 1000 and runs as that user. | Static config points; build and inspect the running UID separately. |
| 8 | Apply `custom-profile` via native AppArmor fields to `prod/secure-app`, and RuntimeDefault seccomp. | MANUAL: profile must load on every eligible Linux node; confirm both denial behavior and application readiness. The staged profile is a starting exercise, not a working nginx policy. |
| 9 | In `kubelet-config.yaml`, disable anonymous authentication and set authorization to Webhook. | MANUAL: copied file only. On a separate VM restart kubelet, test denied unauthenticated access and allowed authenticated access. |
| 10 | Generate a real SPDX SBOM for `nginx:1.24` at `/opt/cks-lab/sbom.spdx` on the node using a trusted installed tool. Recreate `default/multi-pod` without `vulnerable-app`, retaining the Ready `good-app`. | SPDX structure + Ready remaining pod. The removable container is a harmless sleeping fixture. BOM tooling is not preinstalled. |
| 11 | Label `frontend` to enforce Restricted Pod Security. | Label points; separately test rejection of a violating pod and acceptance of a compliant pod, using a version matching the cluster. |
| 12 | Set `database/db-sa` automount to false. Create Ready `database/token-pod` using this SA and nginx, with an explicit token projection mounted at `/var/run/secrets/tokens`, path `token`, audience `api`, expiry 7200 seconds. | Config + readiness. Audience `api` is an exercise target, not a guarantee the API server accepts that token. |
| 13 | Fix the staged audit policy to log all requests at Metadata level, then add policy/log flags and mounts to the copied API server manifest. | MANUAL: the initial policy logs only pods. On a separate VM generate several API operations and inspect actual log records and retention. |
| 14 | Verify `/opt/cks-lab/kube-apiserver-test` against its correctly formatted SHA512 file. Remove only the tampered test file; retain the checksum file. | Successful node evidence read + absent binary. Removal alone does not prove you performed verification. |
| 15 | Change `dmz/web-server` container `httpd` from `httpd:2.4.49` to `httpd:2.4.58`, keeping at least one replica and completing rollout. | Historical image-replacement drill only. These old tags are not current production security recommendations. |
| 16 | Recreate `default/immutable-pod` with a read-only root filesystem and keep it Ready. | SecurityContext + readiness. Full immutability also needs privilege/capability and writable-volume review. |
| 17 | Generate a 32-byte random key for the staged secretbox encryption config, then add the flag/mounts to the copied API server manifest. | MANUAL: on a separate VM preserve key material, enable encryption, rewrite existing Secrets, and inspect raw etcd values. |
| 18 | Create `default/secure-tls` from the jumpbox certificate and key. | TLS type, parseable unexpired certificate, matching private key. |
| 19 | Configure `default/secure-ingress` with a real backend, TLS secret, host, controller-specific redirect, and working HTTPS. | MANUAL: no controller or backend is installed by default. Verify HTTP redirect and HTTPS response. |
| 20 | On a disposable Docker host, remove an unauthorized user from the Docker group and restore socket ownership to root:docker. | MANUAL: no real user/socket damage is staged in this lab. Also check effective sessions and socket permissions. |
| 21 | Scan `httpd:2.4.49` with Trivy, CRITICAL severity only, JSON output at `.cks-state/jumpbox/trivy-report.json` on the Mac. | Report structure, image identity and reported severity; tool/database failures must be handled. |
| 22 | Reduce `rbac/auditor` Role to only get/list core pods. Keep its RoleBinding to SA `rbac/auditor`; eliminate effective secret access and pod/deployment writes. | Exact Role/binding structure plus selected positive/negative `auth can-i` probes. Inspect other bindings too. |

Write down the host, namespace, object and required outcome before starting each task. Budget 120 minutes for a selected unseen set; advanced tasks cannot be completed end to end in the default lightweight baseline.
